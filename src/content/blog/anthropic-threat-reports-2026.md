> ## 要点
>
> - **起点は2025年11月**。Anthropic は、中国の国家支援グループ（GTG-1002）が Claude Code を使って約30組織を狙った「初の AI 主導サイバースパイ活動」を阻止したと公表した。**作戦の80〜90%を AI が実行**した。
> - **2026年6月**、1年分・832アカウントの悪用を **MITRE ATT&CK** にマッピング。中リスク以上の割合は **33%から56%** に増え、「**AI によるオーケストレーションは ATT&CK で表現できない**」と結論づけた。
> - **2026年9月**のレポートは7分野の悪用を公開し、「**高度な攻撃に、高度な攻撃者はもう要らない**」と総括した。2025年11月の自律攻撃の手口が、あらゆる種類の攻撃者に広がった。
> - **蒸留攻撃では中国の7つのラボ**を挙げ、**Alibaba を「これまでに測定した最大の蒸留攻撃」**（2026年5〜7月に1億5,100万回超）と帰属した。6月に報じられた書簡の数値（2,880万回）とは期間も規模も違う。
> - 防御側への示唆は、**静的シグネチャに頼らない検知**、**API キーやセッショントークンを「AI サプライチェーン」として守ること**、そして **AI を防御にも使うこと**。

## はじめに — 3本のレポートの位置づけ

Anthropic は、自社モデルの悪用を検知・阻止した事例を定期的に公開しています。本記事では、そのうち重要な3本と、関連する Alibaba の蒸留攻撃を時系列で整理します。

| 公表日 | タイトル | 内容 |
|:---|:---|:---|
| 2025-11-13 | Disrupting the first reported AI-orchestrated cyber espionage campaign | 初の AI 主導サイバースパイ活動（GTG-1002）の阻止 |
| 2026-02-23 | Detecting and preventing distillation attacks | 蒸留攻撃の初回開示（DeepSeek・Moonshot・MiniMax） |
| 2026-06-03 | What we learned mapping a year's worth of AI-enabled cyber threats | 1年分のサイバー悪用を MITRE ATT&CK で分析 |
| 2026-06（報道） | 上院宛て書簡（原文未公開） | Alibaba による蒸留攻撃を指摘（二次情報） |
| 2026-09-10頃 | Detecting and countering misuse of AI: September 2026 | 2025年12月〜2026年8月の悪用を7分野で公開 |

9月レポートのページには公表日の記載がなく、添付ファイル名から9月10日頃と推定しています。攻撃グループの名前「GTG-○○」は、Anthropic が AI を悪用するアクターに付ける識別子です。**帰属（どの国・組織の仕業か）は、すべて Anthropic の評価を原文の表現に沿って紹介**しています。

## 1. 起点 — 初の AI 主導サイバースパイ活動（2025年11月）

### 1-1. 何が起きたか

- **帰属**: Anthropic は「中国の国家支援グループ（GTG-1002）によるものと高い確度で評価」しています。
- **時期**: 2025年9月中旬に検知し、その後10日間でアカウント停止、影響を受けた組織への通知、当局との連携を行いました。
- **標的**: 大手テック・金融・化学メーカー・政府機関など**約30組織**。侵入に成功したのは「少数」です。

### 1-2. AI がどこまで自律的に動いたか

最大の特徴は、**AI が作戦の80〜90%を独力で実行**したことです。人間の判断が必要だったのは、作戦ごとに4〜6回の重要な局面だけでした。

- **人間**が標的を選び、攻撃用のフレームワークを作った
- **Claude Code** を自律的な侵入テストの指揮役（オーケストレーター）として動かし、ツールは **MCP 経由**で使わせた
- AI は、偵察 → 脆弱性の発見と攻撃コードの作成 → 認証情報の収集 → データの持ち出しと分類 → バックドア設置 → 文書化、までを担った

安全装置をすり抜けるため、攻撃者は**攻撃を無害に見える小さなタスクに分解**し、「正規のセキュリティ企業の社員として防御テストをしている」と偽りました。

### 1-3. 限界 — ハルシネーション

AI は認証情報を捏造したり、公開情報を機密として報告したりしました。Anthropic はこれを「**完全自律のサイバー攻撃への障害**」と表現しています。

## 2. 2026年6月 — 1年分の脅威を MITRE ATT&CK で分析

### 2-1. 分析の方法

- **対象**: 2025年3月〜2026年3月にサイバー関連で停止した **832アカウント**
- **マッピング**: MITRE ATT&CK v18 に対応付け。**13,873の行動、482の固有技術、14の戦術すべて**にわたった
- **リスク評価**: 独自の指標 **ARiES**（AI Risk Enablement Score、0〜100点）。脅威（最大35点）・脆弱性（最大35点）・影響（最大30点）の足し算

### 2-2. 主な結果

| 指標 | 値 |
|:---|:---|
| 最も多かった技術 | マルウェア開発（T1587.001）67.3% |
| 最も多かった戦術 | 防御回避 84.4% |
| 中リスク以上の割合 | 前半33% → 後半56%（約1.7倍） |
| 増えた行動 | アカウント探索 +8.9%、自動データ持ち出し +6.2% |
| 減った行動 | フィッシング −8.6%、能力開発 −12% |
| Claude Code の利用 | 攻撃者の80% |

### 2-3. 3つの結論

1. **攻撃者は AI を、攻撃の後段の複雑な工程で使うようになっている**
2. **自律化が進み、従来の「高リスクか低リスクか」の判別指標が効かなくなっている**
3. **ATT&CK は AI によるオーケストレーションを表現できていない**

3つ目を象徴するのが、第1章の GTG-1002 です。使った技術は30・戦術は13で、数だけ見れば中リスク相当でした。しかし ARiES では**満点の100点**です。Anthropic は「この種のエージェント的オーケストレーションに対応する ATT&CK の ID は存在しない」と指摘し、**工程内の自律実行、リアルタイムの判断、複数工程の自律的な連鎖**を捉える観点が足りないとしています。ATT&CK の拡張については MITRE と協議中です。

## 3. 2026年9月 — 7分野の悪用レポート

### 3-1. 全体像

2025年12月〜2026年8月に検知・対処した悪用を、**サイバー作戦・影響工作・監視・詐欺・生物関連・通常兵器・蒸留**の7分野で公開しています。悪用に使われたのは Claude の Haiku・Sonnet・Opus で、「**蒸留の1件を除き、Fable や Mythos 級のモデルが使われた事例はない**」とされています（その1件がどれかは明示されていません）。

### 3-2. サイバー作戦 — 「アシスタントから指揮役へ」

レポートの中心メッセージは「**高度な攻撃に、高度な攻撃者はもう要らない**」です。

- **2025年11月に記録した自律攻撃の手口が、調査したあらゆる種類の攻撃者に広がった**。公開されている攻撃エージェントのフレームワークも一因
- 大半の作戦は AI の直接実行か指揮によるもので、**人間の役割は標的の設定と持ち出したデータの確認**に縮んだ
- **検知されると AI が自動でツールを作り直す**ため、静的シグネチャで攻撃側にコストを課す手が効かなくなった
- **AI のサプライチェーン（API キーやセッショントークン）が、犯罪の標的・戦利品・攻撃用の計算資源**になった

| 識別子 | Anthropic の評価 | 主な手口 |
|:---|:---|:---|
| GTG-20006 | ロシアの諜報活動。Midnight Blizzard と結び付ける公開報道と整合 | AI エージェントが自前マルウェアの検知状況を監視し、検知されると自律的に改変・再ビルド。フィッシング基盤の構築から C2 監視まで自動化 |
| GTG-10007 | 中国語話者の「エクスプロイト工場」 | 親エージェントが作業を分解して並列のサブエージェントに割り振る方式で約50組織を標的化。ネットワーク機器で1か月に「10件を超えるゼロデイの可能性」 |
| GTG-50014 | 金銭目的の複数クラスター | 180万本の Android アプリから認証情報を収集し、SaaS 事業者を経由して下流の顧客を恐喝 |
| GTG-50020 | ロシア語話者、金銭目的 | AI ベンダーの評価サンドボックスへのプロンプトインジェクションで本番 API キーを窃取。約4日で約30社を攻撃（Anthropic 自身は侵害されていない） |
| GTG-50021 | 偽の Claude 再販業者 | 実際は別のモデルに通信を流し、顧客の資格情報を窃取 |

### 3-3. その他の分野

- **影響工作**: 約70の偽ニュースサイトで20言語・8,900本超の記事を配信した事例や、約1,000の偽 X アカウントで選挙を狙った事例など。**影響工作のサービス化**、AI が編集部の役割を担うこと、出自の洗浄が傾向として挙がった。多くは実際の聴衆に届いていない
- **監視**: 約2,500万枚の SIM を監視する設計のシステムなど。**AI が技術者集団そのものを置き換え**、国家の治安機構に組み込まれつつあると指摘
- **詐欺**: 20超の偽出会い系アプリで、2026年4月の2週間に4,700超の AI ペルソナが2万5,000人以上とやり取りした事例
- **通常兵器**: 6事例。対策として高威力爆発物・兵器開発向けの新しい分類器を導入
- **生物関連**: 5事例（研究機関・国・病原体は伏せられている）。**高リスクのバイオ能力は、信頼できる利用者向けプログラムで提供するのが唯一安全な方法**と結論

## 4. 蒸留攻撃 — 中国の7つのラボと Alibaba

### 4-1. 蒸留攻撃とは

レポートの定義は「**許可なくモデルの能力を抜き出す、産業規模の隠れたキャンペーン**」です。Claude の回答や推論過程を大量に集め、自社モデルの学習データにします。2026年2月の初回開示以降、**中国の7つのラボ**による攻撃を阻止したとしています。

手口は大きく2つに分かれます。

- **大量アクセスの確保**: 中継業者経由のアクセス、偽の身元・盗難カード・盗難 API キーによる大量のアカウント作成、再販業者からの会話ログ購入、自社サービスの利用者の要求を無断で Claude に転送
- **推論過程の引き出し**: 推論を抜き出していると検知されないよう指示を偽装する、偽のシステムプロンプトで推論を出力させる、1万2,000件を超える手法テストで成功した方法を本番に使う、など

### 4-2. ラボ別の規模（9月レポート）

| 識別子 | Anthropic の帰属 | 主な内容 | 観測された規模 |
|:---|:---|:---|:---|
| GTG-16005 | Alibaba（Qwen / Tongyi Lab） | **「これまでに測定した最大の蒸留攻撃」**。Opus 4.6 / 4.7 の推論過程を集めて学習データ化し、Qwen 3.5〜3.7 の学習に使用。ピーク時は1日約300万回・3,500超アカウント | 2026年5〜7月に1億5,100万回超 |
| GTG-16002 | Moonshot | Kimi の代わりに Claude を無断で提供。偽アカウント5,380件 | 5〜7月に2,300万回超 |
| GTG-16001 | DeepSeek | Claude Code などの利用者を判別して Opus に転送 | 7月の14日間で1,210万回超 |
| GTG-16006 | Zhipu（Z.ai） | 当初 Fable を狙ったが防御で断念し、Opus 系に移行 | 17日間で340万回超 |
| GTG-16008 | Xiaomi（MiMo） | 1,500超のアカウント | 2026年3〜4月の20日間で40万回超 |

このほか SenseTime と MiniMax も、購入した会話ログの利用やダミー会社名義の中継網で名前が挙がっています。

### 4-3. 6月の書簡と9月レポートの違い

Alibaba の件は、6月に「Anthropic が上院に書簡を送った」と報じられていました。ただし**書簡の原文は公開されておらず**、数値は報道によるものです。9月レポートとは期間も規模も異なります。

| 項目 | 6月の書簡（報道・二次情報） | 9月レポート（一次情報） |
|:---|:---|:---|
| 期間 | 2026-04-22〜06-05（44日間） | 2026年5〜7月 |
| 規模 | 約2万5,000アカウント・2,880万回 | 1億5,100万回超（ピーク時3,500超アカウント） |
| 表現 | 「これまでで最大の蒸留攻撃」 | 「これまでに測定した最大の蒸留攻撃」 |

9月レポートは書簡に言及していません。**Alibaba 側の反応は、主要な報道では「コメント要請に応じず」**で、否定声明の原文は確認できていません。報道によれば、書簡は蒸留を行う企業への罰則の立法や半導体輸出規制の強化も提言しています。

### 4-4. Anthropic の対策

- 中継網をメタデータから特定し、**組織単位で帰属させて一括で措置**する
- 推論の抜き出しを検知する専用の分類器
- 推論の内容を要約してから返す
- **Preserved Thinking**（Fable 5.1・Opus 5.5）: 新しい API アカウントでは、推論より前にあるシステムプロンプト・ツール・メッセージを書き換えて再送できない
- 非対応国からの利用が疑われる場合の本人確認

Preserved Thinking が開発者に与える影響は [Claude Opus 5.5 完全ガイド](/mdTechKnowledge/blog/claude-opus-5-5-guide/) の第5章で解説しています。

## 5. 3本から読み取れるトレンド

1. **自律化の一般化**: 2025年11月に「初」として報告された AI 主導の攻撃が、10か月後には「あらゆる種類の攻撃者」の標準的な手口になった
2. **攻撃の高度さで攻撃者を見分けられない**: 学部生とみられる集団が、ゼロデイ候補を1か月で10件以上見つけるようになった
3. **既存の枠組みが追いつかない**: ATT&CK は AI の指揮を表現できず、静的シグネチャは AI の自動改変で効かなくなった
4. **AI そのものが標的になった**: API キーやセッショントークンが盗まれ、モデルの能力そのものが蒸留で抜き取られている

## 6. 防御側への示唆

Anthropic の推奨と、レポートの内容から導ける実務上の対策です。

- **AI を防御にも使う**: SOC の自動化、脅威検知、脆弱性評価、インシデント対応
- **静的シグネチャに頼らない検知**: 振る舞いベースの検知と、多段階の自律実行や MCP の操作を捉える監視
- **API キーを「AI サプライチェーン」として守る**: 評価用のサンドボックスに本番キーを置かない、キーの権限と有効期限を絞る、使用状況を監視する
- **非公式の Claude 再販業者を使わない**: 偽の再販業者が資格情報を盗む事例が出ている
- **パッチ適用を早める**: 公開された脆弱性が AI で短時間に悪用される前提に立つ
- **脅威情報を共有する**: レポートには侵害の痕跡（IOC）の CSV が添付されている

## まとめ

- Anthropic の脅威レポートは、**「AI が攻撃を手伝う」段階から「AI が攻撃を指揮する」段階への移行**を、2025年11月から2026年9月にかけて記録している。
- **2026年6月の ATT&CK 分析**は、AI のオーケストレーションが既存の枠組みで表現できないことを数値で示した。
- **2026年9月のレポート**は、自律攻撃の一般化と、AI サプライチェーンやモデルの能力そのものが標的になっている現状を示した。
- **Alibaba の蒸留攻撃**は、6月の報道と9月の一次情報で数値が異なる。引用するときは出所を区別する必要がある。
