> ## 要点
>
> - **Claude Duet は「先に動く」別アプリ**です。2026年10月21日（PT）に研究プレビューが始まりました。ユーザーがチャットを開くのを待つ従来の Claude と違い、Duet は**注意が必要なことを自分から知らせ、頼んだ作業を進め、離席中も動き続け、実行前に確認します**（公式の説明）。
> - **対象は限定的**です。ウェイトリスト制で、まず**米国の Pro・Max・Ultra** の契約者。**Team と Enterprise は現時点で対象外**です。独立した iOS／Android アプリと claude.ai で使え、**利用上限は Claude のプランと共有**します。
> - **動作の中心は Opus 5.5** で、専用の**仮想マシン（独自のブラウザ付き）**上で動きます。PC やスマホを起動しておく必要はありません。
> - **安全設計の柱は「承認」と「資格情報を見せない」こと**です。メッセージの送信・支払い・書類への署名・削除は、実行前に必ず確認します。パスワードやサインイン用トークンは直接見ません。
> - **限界は公式が明記**しています。スレッドの読み違い、緊急度の誤判定、チケット予約のような私的な用事、ブラウザ画面の共有未対応などです。
> - **API バージョン `2026-10-21` とは別の話題**です。Duet の発表と同じ日付ですが、公式の資料に両者を結びつける記述は見つかりませんでした（第9章）。

## 1. Claude Duet とは何か

公式ページは、Duet を「Claude がプロアクティブなエージェントとして働く新しいアプリ」と説明しています。想定する利用者は、**追うべきことが多すぎる専門職や小規模事業者**です（Anthropic の説明、MacRumors も同趣旨で報道）。

Anthropic は、従来の Claude との違いを次のように説明しています。

| | 従来の Claude | Claude Duet |
|:---|:---|:---|
| 動き出すきっかけ | あなたがチャットを開く | **Duet の側から**、注意が必要なことを知らせる |
| 離席中 | 止まる | **作業を続ける** |
| 実行前 | （ツール使用時の許可など） | 送信・支払い・署名・削除は**事前に確認** |
| 入口 | claude.ai、各アプリ | **別アプリ**（iOS／Android、claude.ai） |

公式は、Duet と主要な Claude アプリの関係について「早期ユーザーから学んだことが、両者の連携のしかたを形づくる」と述べています。つまり**当面は別アプリとして切り離されており、統合の方針は未定**です。

## 3. 仕組み — ブリーフ・確認・通知

公式ページから確認できる動作は、次のとおりです。

- **朝のブリーフ**: 毎朝、接続したアプリ全体から最も重要な項目を短くまとめて届けます。次の一手の下書きも用意します。
- **数時間おきの確認**: 接続アカウントを「数時間おき」に確認します（利用上限を抑えるため）。**何を、どのくらいの頻度で知らせるかは設定できます**。
- **通知**: 注意が必要なとき、およびバックグラウンドの作業が終わったとき、確認が必要なときにメッセージします。
- **大きな作業**: 会議の調整やダッシュボードの作成などを任せ、完成した文書・スプレッドシート・スライドをレビュー用に返します。
- **専用の仮想マシン**: 独自のブラウザを持つ仮想マシン上で動くため、**ノート PC やスマホを起動しておく必要がありません**。承認・ログイン・安全性のチェックも、このクラウド上のコンピュータで行われます。
- **1本のスレッド**: 文字または音声の**1本の長いスレッド**で、手短な返信も長い案件も扱います。プロンプトや事前設定は不要です。
- **Claude アカウントの引き継ぎ**: メモリ、スキル、接続済みアプリが引き継がれます。

**確認の間に届いたものは見逃し得る**ことも、公式 FAQ が認めています。数時間おきの確認という設計上、リアルタイムの監視ではありません。

- **接続したアプリはいつでも切断できます。**

## 5. 承認と安全性 — Duet の設計の核心

### 5-1. 承認が必要な操作

- **事前確認なしで行う**: 読み取りと下書き。
- **実行前に内容を見せて承認を待つ**: **メッセージの送信、支払い、書類への署名、削除**。
- **承認があっても許可されない**: **有価証券の売買、口座間の資金移動**など。
- 行動の承認には、Anthropic の **auto mode の分類器**が使われます（Claude Code の auto mode については [auto mode ガイド](/mdTechKnowledge/blog/claude-code-auto-mode-guide/) を参照）。

### 5-2. 支払い

- 購入は **Stripe の Link ウォレット**を通じて行います。Duet が購入内容を確認し、Link があなたに支出の承認を求め、支払いは**仮想カード**で行われるため、実際のカード番号は共有されません。
- **Shop Pay** でのチェックアウトにも対応します。

### 5-3. 資格情報と機微情報

- 資格情報の扱いは **Claude Managed Agents** の設計に従い、Duet は**パスワードやサインイン用トークンを直接見ません**（Managed Agents については [Managed Agents ガイド](/mdTechKnowledge/blog/claude-managed-agents-guide/) を参照）。
- 機微情報には、**専用の分類器とシステムプロンプトが各メッセージを検査**します。最も厳格な区分（クレジットカード番号や政府発行 ID など）の共有要求は**拒否するように設計**されています。健康情報や個人の財務情報などは、**ユーザーが明示的に指示したときだけ**共有されます。

### 5-4. 攻撃への備え

- **隠れた指示とプロンプトインジェクション**への防御は、Anthropic のブラウザ利用の研究に基づきます。
- 公式は、**レッドチームと外部企業によるペネトレーションテスト**を行ったこと、Duet が**公開バグバウンティ**の対象であることを述べています。
- **2026年10月23日**に、公式ページは安全性の更新を追記しました。本文は「これらの保護の開発と強化を続けている」とあり、詳細は別の記事へのリンクです。**そのリンク先は今回確認できていません**。Anthropic は「安全設計の詳細を数日以内に共有する」とも述べています。
- 「いつメッセージするか」という判断についても、公式は「テストを続けている」と述べています。

> 公式ページ自体が、**完全なデータ保持・プライバシーポリシーは載せていません**。業務データを扱わせる前に、保持期間や学習利用の扱いは別途確認が必要です。

## 6. 公式が認める限界

- スレッドを**読み違える**、緊急度を**見誤る**ことがある。
- **私的な用事**（チケット予約など）は、仕事のタスクより弱い。
- **ブラウザ画面をユーザーに見せることはまだできない**。
- 主要な Claude アプリとは**別アプリ**である。
- バックグラウンドの確認と大きな作業は**利用上限を消費**する。確認間隔が数時間おきなので、間に届いたものを見落とすことがある。

## 7. Cowork・Claude Code・Routines との使い分け

公式ページは Duet を Cowork や Routines と直接比較していません。以下は、各製品の既知の性質を踏まえた**本稿の整理**です。

| 観点 | Claude Duet | Claude Cowork | Claude Code | Routines |
|:---|:---|:---|:---|:---|
| 動き出すきっかけ | **Duet の側から**（ブリーフ・確認・通知） | あなたの指示 | あなたの指示 | スケジュールなど、**あらかじめ決めた条件** |
| 主な用途 | 個人・小規模事業の**見張りと段取り**（メール・予定・請求など） | デスクトップ上で進める作業 | コードを書く・直す | 決まった手順の定期実行 |
| 動作場所 | **専用の仮想マシン**（端末不要） | デスクトップ（リモート利用もあり） | 端末（ローカル） | クラウド |
| 承認の考え方 | 送信・支払い・署名・削除は**事前承認** | セッション内で確認 | 権限モードによる | 事前に決めた範囲 |
| 提供条件 | 米国の Pro/Max/Ultra（ウェイトリスト） | [Cowork の記事](/mdTechKnowledge/blog/claude-cowork-updates/)を参照 | 各記事を参照 | [Routines の記事](/mdTechKnowledge/blog/claude-code-routines-guide/)を参照 |

選び方の目安（本稿の見解）:

- **自分が指示して進める作業**は、Cowork や Claude Code。
- **決まった手順を決まった時刻に**回すなら、[Routines](/mdTechKnowledge/blog/claude-code-routines-guide/)。
- **「何が起きているか」を先に知らせてほしい個人用途**で、承認を挟みながら任せたいなら Duet。

Cowork・Claude Code・Web 版などの入口の全体像は [Claude のアクセス方法の記事](/mdTechKnowledge/blog/claude-access-methods-overview/) にあります。Duet は研究プレビューで対象も限られるため、そこでは4系統の早見表には加えていません。

## 8. 競合との位置づけ（報道ベース）

MacRumors は、Duet を **Meta の Muse エージェント**と **OpenAI の Dots エージェント**に対する Anthropic の答えとして位置づけています。3つとも「ユーザーが聞く前に動き出す」エージェントという枠組みです。ただしこの比較は**報道側の整理**で、Anthropic 自身が競合を名指ししたわけではありません。Muse と Dots の機能の詳細比較は、今回確認できた一次情報にはありませんでした。

## 9. API バージョン 2026-10-21 との関係

Duet の研究プレビューと **API バージョン `2026-10-21`** は、同じ10月21日付の発表ですが、**別の話題**です。API バージョンの変更は、`temperature` などのサンプリング指定の削除や SDK の仕様変更など、API 利用者向けの破壊的変更が中心で（[Messages API 新機能ガイド](/mdTechKnowledge/blog/anthropic-messages-api-new-features-2026/)の第27章を参照）、Duet の公式ページやリリースノートには、API バージョンとの関係を示す記述がありませんでした。Duet を API で組み込む方法も、現時点では公開されていません。

## 10. 導入前に確認したいこと

1. **対象かどうか**: 米国の Pro/Max/Ultra で、ウェイトリストに登録できるか。Team・Enterprise は対象外。
2. **接続するアプリの範囲**: 最小限から始め、不要になれば切断する。
3. **承認の運用**: 送信・支払い・署名・削除は毎回確認が入る。承認しても不可の操作（有価証券の売買、口座間の資金移動）も把握しておく。
4. **利用上限への影響**: バックグラウンドの確認が上限を消費する。
5. **プライバシー**: データ保持の詳細は公式ページに載っていない。業務データを接続する前に確認する。
6. **更新の追跡**: 10月23日の安全性の更新の詳細や、1Password・Shopify の追加が今後予定されている。

## まとめ

- Duet は**ユーザーが開く前に動き出す**ことを軸にした別アプリで、**専用の仮想マシン**、**1本のスレッド**、**承認つきの実行**が特徴です。
- 安全設計は、**事前承認、資格情報を直接見ない構造、機微情報の分類器、外部のペネトレーションテスト、公開バグバウンティ**という複数の層で説明されています。ただし**プライバシーの詳細は未公開**で、公式も更新を続けると述べています。
- 対象は**米国の Pro/Max/Ultra のウェイトリスト**に限られ、Team・Enterprise は含まれません。既存の Cowork・Claude Code・Routines とは役割が違うため、**併用して使い分ける**のが現実的です。
