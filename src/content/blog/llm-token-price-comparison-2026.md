## §1. なぜ今「トークンエコノミー」か — 「フロンティア一択」の終わり

2025年までの合言葉は「**とりあえず一番賢いモデルを使う**」でした。しかし2026年、状況は変わりました。

1. **モデルが階層化した**。同一ベンダー内でもフロンティア級（Opus 5.5 / GPT-6 Astra / Gemini 3.1 Pro）から軽量級（Haiku 4.5 / Flash-Lite / GPT-6 Luna）まで、**出力単価で 10〜100 倍の開き**があります。
2. **エージェント化で消費量が桁違いに増えた**。1リクエスト＝数百トークンだった時代から、**1タスクで数百万トークン**を消費する自律エージェントの時代へ。単価差がそのまま請求額の桁差になります。
3. **コストが経営指標になった**。金融機関からは「**AI トークンコストが業績・相場の新たな変数**」との指摘も出ており、企業では **FinOps（クラウド原価管理）の対象**として AI 支出を可視化・制御する動きが加速しています。

つまり、**「賢さ」だけでなく「単価×実消費トークン数＝実効コスト」で設計する**——これがトークンエコノミーの基本です。特に企業では、**全社員が全タスクでフロンティアを叩く**運用はコスト的に持続しません。

## §3. 「Copilot」はトークン単価を持たない — 課金構造の3類型

「Copilot のトークン単価は？」という問いには**注意が必要**です。**GitHub Copilot は独自のトークン単価を持たず、上記のモデルを"再販"している**からです。Microsoft 系は次の3つで課金構造がまったく異なります。

| 製品 | 課金モデル | トークン単価 | 中身 |
|:---|:---|:---|:---|
| **GitHub Copilot** | **使用量課金**（2026-06-01〜） | **持たない（各社の定価で再販）** | 月額＋AIクレジット枠（1クレジット＝$0.01）。**各モデルを提供元の定価でクレジット消費**し、枠を超えると追加課金。**モデル乗数（旧プレミアムリクエスト倍率）は旧年額プランの利用者にだけ残る**。GPT-6 Astra は 2026-09-04 から Pro+ / Max / Business / Enterprise で利用可。プラン月額は Pro $10 / Pro+ $39 / Max $100 / Business $19 / Enterprise $39（2026年7月時点） |
| **Microsoft 365 Copilot** | **座席課金** | **なし（従量ではない）** | **Business $21/user・月**（年払い促進 $18）／**Enterprise $30/user・月**（2026年7月時点）。M365 ベースライセンスへのアドオン。トークンは使い放題に近い定額 |
| **Azure OpenAI** | **トークン従量** | **あり（素の単価）** | GPT を **§2 の GPT 単価**で提供（US Data Zone は10%上乗せ）。**Copilot の"下"で動く基盤**。IaC・VNet・データレジデンシーを自社管理したい企業向け |

> **核心**: GitHub Copilot の課金は**「定価×トークン数をクレジットで払う」形になり、以前より見積もりやすくなりました**。ただし**月額に含まれるクレジット枠を超えた分が追加課金**になる点と、**Copilot 側のモデル提供期間が各社の API と一致しない**点に注意が必要です。たとえば Copilot では Gemini 3.1 Pro が2026-09-01に提供終了し、Gemini 3.5 Flash / 3.6 Flash も2026-10-02に終了予定です（後継は 3.8 Flash）。M365 Copilot は**座席定額**（重量ユーザーほど割安、ライトユーザーほど割高）。**"トークン単価表"だけでは Copilot のコストは見積もれない**点を、企業の調達・FinOps は押さえる必要があります。

## §4.【本題】フロンティア×安価モデルの役割分担設計

コストを制御する鍵は、**「1つのモデルで全部やらない」**ことです。**難しい判断はフロンティア、定型の量産は安価モデル**に分ける——これがトークンエコノミーの中核設計です。

### どちらが何を担うか

| 観点 | **フロンティア級**（Opus 5.5 / GPT-6 Astra / Gemini 3.1 Pro / Fable 5.1） | **安価級**（Haiku 4.5 / Flash-Lite / GPT-6 Luna / DeepSeek V4.1-Flash） |
|:---|:---|:---|
| **得意** | 曖昧性の解消、多段推論、**計画・タスク分解**、**プロンプト/スキーマ設計**、最終検証、難所のデバッグ | 定型実行、大量並列、抽出・分類・整形、要約、単純変換、低レイテンシ処理 |
| **担う工程** | 「**設計図を描く**」「**難しい1件**を解く」「**品質のゲート**」 | 「**設計図どおり量産する**」「**簡単な大量件**をさばく」 |
| **出力単価** | 高（$12〜$50/MTok） | 低（$0.4〜$5/MTok） |
| **原則** | **少ない回数**だけ呼ぶ | **大量に**呼ぶ |

### 実装パターン集

**(a) プロンプト/スキーマ設計はフロンティア → 実行は安価**（最も基本・ご提示の形）
フロンティアに**「曖昧さのない厳密なプロンプト」や「出力スキーマ（JSON 定義）」を1回だけ設計**させ、以降の**量産実行は安価モデル**が担う。例: 契約書1万件からの項目抽出で、抽出ルールとfew-shot例を Opus 5.5 が設計 → 実際の抽出は軽量級が1万回実行。**設計コストは定数**で、実行の出力単価は Haiku 4.5 なら Opus 5.5 の1/4、Gemini 3.1 Flash-Lite なら約1/13、GPT-6 Luna なら1/40 になる。

**(b) ルーター（難易度で振り分け）**
入力を**軽量モデル（または分類器）が難易度判定**し、簡単な案件は安価モデル、難しい案件だけフロンティアへ。カスタマーサポートの一次応答などに有効。

**(c) カスケード（安価→失敗時だけ昇格）**
まず**安価モデルで試行**し、**信頼度が低い/検証に落ちた案件だけフロンティアへエスカレーション**。多くの案件は安価で完結するため、平均単価が下がる。

**(d) オーケストレーション（計画＝フロンティア、実行＝安価並列、統合＝フロンティア）**
フロンティアが**タスクを分解して計画**し、**安価なサブエージェントが並列実行**、最後にフロンティアが**統合・検証**。Claude Code の **Explore エージェントや Dynamic Workflows**（サブエージェントのファンアウト）はまさにこの構造で、[Dynamic Workflows 完全ガイド](/mdTechKnowledge/blog/claude-code-dynamic-workflows-guide/) の考え方が応用できます。

**(e) 生成と検証を分ける（generate-and-verify / adversarial verify）**
**安価モデルが大量生成 → フロンティアが検証/採点**（または逆に、フロンティアが1つの正解を作り安価が横展開）。品質のゲートだけ高いモデルに任せることで、生成コストを抑えつつ品質を担保。

**(f) 蒸留・ゴールデン例で安価を底上げ**
フロンティアで**教師データ（ゴールデン例）**を作り、それを**few-shot / ファインチューニング**で安価モデルに与える。安価モデルの精度を、特定タスクに限ってフロンティア近くまで引き上げる。

**(g) Batch＆キャッシュを安価層に重ねる**
即時性の要らない大量処理は **Batch（−50%）**、繰り返す長い前提文は **プロンプトキャッシュ（入力−最大90%以上）**。**安価モデル×Batch×キャッシュ**の三段重ねで、実効単価はさらに1桁下がる。DeepSeek のように**時間帯割引**を持つモデルなら、夜間バッチに寄せるだけでも半額になる。

### 削減の概算

> 例: **1万件の定型抽出**タスク。
> - **全部 Opus 5.5**: 1万回 × フロンティア単価 → 仮に **$200/回相当の重い処理なら数千ドル規模**。
> - **設計のみ Opus 5.5（数回）＋実行 Gemini 3.1 Flash-Lite（1万回）**: 実行の単価が入力で1/16、出力で約1/13。**総額はおおむね1/10前後**に。
>
> 精度が要件を満たす限り、**「計画はフロンティア・実行は安価」に切り替えるだけで一桁のコスト削減**が現実的です（実際の削減率はタスクの検証・エスカレーション率に依存）。

## §5. 企業のコストガードレール（実装）

役割分担を「設計」だけで終わらせず、**組織のガードレール**として仕組み化します。

- **モデル・エンタイトルメント / デフォルトモデル制限**: ロール別に使えるモデルを制限し、既定を安価モデルにする（無自覚なフロンティア濫用を防ぐ）。
- **支出アラート**: 組織 75% / 90%、ユーザー 75% / 95% で通知。→ [Anthropic Enterprise Analytics API 完全ガイド](/mdTechKnowledge/blog/anthropic-enterprise-analytics-api/) を参照。
- **利用実績の可視化・FinOps 連携**: Analytics API を Datadog / CloudZero に流し、**チーム・モデル別の原価**を追跡。
- **Batch / キャッシュの標準化**: 即時不要なジョブは Batch、長い共通前提はキャッシュを"規約"にする。
- **期限付き価格の管理**: プロモ・導入価格（GPT-5.6 Sol、Gemini 3.6〜3.8 Flash）で組んだ予算は、**期限後の正規価格でも破綻しないか**を事前に試算しておく。
- **レート上限の把握**: [Rate Limits API 完全ガイド](/mdTechKnowledge/blog/anthropic-rate-limits-api-guide/) でティア・残量をプログラム監視。

## まとめ

- **同じタスクでもモデル次第でコストは100倍以上変わる**。2026年は「フロンティア一択」ではなく、**単価×実トークン数の実効コスト**で設計する時代。
- **2026年9月は最上位（GPT-6 Astra・Fable 5.1 が $50）と最軽量（GPT-6 Luna $0.50 など）の両極化が進んだ**。GPT-5.6 の値下げ、Gemini Flash の導入価格、Opus 5.5 の単価20%減と、価格破壊は続いている。
- **安値の一部は期限付き**（GPT-5.6 Sol は少なくとも11/21まで、Gemini 3.6〜3.8 Flash は12/31まで）。長期予算は正規価格で。
- **GitHub Copilot は乗数を廃止し定価でクレジット消費**、**M365 Copilot は座席課金**、**Azure OpenAI は素のトークン従量**。**"どの窓口で叩くか"で実効コストが変わる**。
- **本質は役割分担**: **正確なプロンプト/スキーマ・計画・検証はフロンティア、量産実行は安価モデル**。ルーター／カスケード／オーケストレーション／Batch・キャッシュを組めば、品質を保ったまま一桁のコスト削減が狙える。
- 企業は**エンタイトルメント・支出アラート・FinOps 連携**でこれを仕組み化する。

## 注意事項

- **価格・クレジット枠は頻繁に改定**されます。本記事は **2026年9月26日時点**の各社公表値に基づく目安であり、**必ず各社公式ページで最終確認**してください。
- **期限付きの価格が複数あります**。GPT-5.6 Sol（$4/$20）は「少なくとも2026-11-21まで」のプロモ価格、Gemini 3.6 / 3.7 / 3.8 Flash（$0.75/$3.75）は2026-12-31までの導入価格です。
- **トークナイザはモデルごとに異なり、同一テキストでも実消費トークン数が変わります**（例: Claude Fable 5 / 5.1 は約30%増）。また Kimi K3・Gemini・DeepSeek のように**思考トークンを出力として課金**するモデルが多いため、**「単価」だけでなく「単価×実トークン数」**で比較してください。
- 米3社以外（xAI・Alibaba・DeepSeek・Z.ai・Mistral・Moonshot AI）の単価は各社の公式料金ページで確認した値です。Meta の Muse Spark は公式の料金ページを確認できなかったため掲載していません。
- GitHub Copilot のクレジット枠・M365 Copilot の座席条件は改定が多く、**契約前に最新の課金ドキュメント**を確認してください。
