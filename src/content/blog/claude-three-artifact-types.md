> ## 要点
>
> - Claude の「アーティファクト」は**同名の別機能が3種類**ある。**保存場所・一覧の置き場所・共有可否・更新の仕組みがすべて違う**。
> - **① claude.ai チャットのアーティファクト**: claude.ai の**サーバー保存**。**端末をまたいで見られる**。**Free / Pro / Max で公開リンクを発行可能**。
> - **② Cowork のライブアーティファクト**: **「あなたのコンピュータ上に存在する」**（公式表現）。**デスクトップアプリ専用**で、**端末を移行しても一緒には移動しない**。**開くたびに接続済みアプリから最新データを取得**し、ヘッダーに手動更新ボタンもある。**Pro / Max では共有も公開も不可**（Team / Enterprise のみ）。
> - **③ Claude Code のアーティファクト**: URL は `claude.ai/code/artifact/<id>`、一覧は**専用ギャラリー** `claude.ai/code/artifacts`。**CLI かデスクトップアプリからのみ発行**でき、モバイルからは作れない。
> - **「ライブなのに自動更新されない」ことがある**。ライブアーティファクトの仕組み自体は自動更新だが、**中身がコネクタを呼ばずデータを直接埋め込んだ静的HTML**なら当然更新されない。**リモートセッションから作った場合はコネクタ権限が付与されない状態で始まる**点も要注意。
> - **公開解除（unpublish）は一方通行**。**同じアーティファクトを再公開することはできず**、永続ストレージを使っていた場合は**データも完全に削除**される。

## はじめに — なぜ混乱するのか

「PCで作ったアーティファクトが iPhone の一覧に出てこない」「共有リンクが発行できない」「ライブと書いてあるのに更新されない」——こうした症状は、**多くの場合は不具合ではなく、3つの別機能を1つだと思っていることが原因**です。

Anthropic は現在、**同じ「アーティファクト（Artifacts）」という名前**で、**設計思想の異なる3つの機能**を提供しています。名前が同じなので同一機能の別画面だと受け取られがちですが、実際には**保存場所からして違います**。片方はクラウド、もう片方は**あなたのPCのローカル**です。

本記事では、公式ヘルプセンターと Claude Code 公式ドキュメントに基づいて、3種類を横断的に整理し直します。

## 1. 全体像 — 3種類の比較

| 観点 | **① claude.ai チャット** | **② Cowork ライブアーティファクト** | **③ Claude Code** |
|:---|:---|:---|:---|
| **保存場所** | **claude.ai のサーバー** | **あなたのコンピュータ（ローカル）** | claude.ai のサーバー |
| **端末をまたげるか** | **○ またげる** | **× 移行しても一緒に移動しない** | ○ またげる |
| **作れる場所** | claude.ai の会話全般（Web / デスクトップ / **モバイル**） | **デスクトップアプリのみ**（macOS / Windows / Linux beta） | **Claude Code CLI**（v2.1.183+）または**デスクトップアプリ**（v1.13576.0+） |
| **一覧の置き場所** | claude.ai サイドバーの Artifacts | **デスクトップアプリの Artifacts ビュー**（Web / モバイルには出ない） | **専用ギャラリー** `claude.ai/code/artifacts` |
| **URL 形式** | 公開時に公開リンクを発行 | （ローカル。共有時は組織内リンク） | `claude.ai/code/artifact/<id>` |
| **データ更新** | 静的（作った時点の内容） | **開くたびにコネクタから最新データを取得**＋手動更新ボタン | セッションが進むと**その場で更新**（republish） |
| **公開リンク** | **Free / Pro / Max で可能** | **Pro / Max は不可**（Team / Enterprise のみ・組織内共有） | Pro / Max は**公開リンクのみ**、Team / Enterprise は組織内共有も可 |
| **必要プラン** | Free 以上 | **有料プランのみ**（Pro / Max / Team / Enterprise） | Pro / Max / Team / Enterprise |

**要するに、②だけが「ローカルに存在するアプリ」に近く、①③は「クラウドに置かれたページ」です。** この一点を押さえると、症状の大半が説明できます。

## 2. ① claude.ai チャットのアーティファクト

もっとも古くからある、いわゆる「普通のアーティファクト」です。

### 特徴

- 通常の claude.ai の会話中に、Claude が**まとまった自己完結的な成果物**（目安として15行を超えるコードや文書など）を作ると、チャット画面の右側に専用ウィンドウとして表示される
- 対応形式は幅広く、**コード・SVG・Mermaid 図・React コンポーネント・HTML ページ・Markdown 文書・ダウンロード可能ファイル（.docx / .pptx / .xlsx / .pdf）・PDF レンダリング**など
- **claude.ai のサーバーに保存**されるため、**PCで作ってスマホで見る**ことができる

### 公開（Publish）

**Free / Pro / Max プランで公開が可能**です。**Publish** ボタンを押すと公開リンクが発行され、**Claude アカウントを持たない人でも閲覧・操作できます**。Claude ユーザーであれば、閲覧・操作に加えて**コードのコピー**も可能です。

> **「Remix」ボタンは廃止されました。** 現在は「**コードを新しいチャットにコピーする**」方法に置き換えられています。改変したい場合は、コードをコピーして新しい会話で Claude に依頼します。

### ⚠️ 公開解除（unpublish）は一方通行

これは3種類のなかでも**特に事故りやすい仕様**です。

> **一度アーティファクトの公開を解除すると、同じアーティファクトを再度公開することはできません。** 後で公開したい場合は、**新しいアーティファクトを作成する必要があります**。

さらに、**永続ストレージを使っていたアーティファクトの場合、公開解除は関連するストレージデータ（個人・共有の両方）を完全に削除**します。

**「いったん公開を止めて、直してからまた公開しよう」という運用はできません。** 公開URLを維持したまま内容を更新する形にするか、そもそも公開解除しない方が安全です。

## 3. ② Cowork のライブアーティファクト — 最も誤解が多い

Claude Cowork で作られる**永続的でインタラクティブな HTML ダッシュボード**です。3種類のなかで**最も性質が異なり、最も誤解されやすい**のがこれです。

### 保存場所は「あなたのコンピュータ」

公式ヘルプの表現がすべてを物語っています。

> **ライブアーティファクトはあなたのコンピュータ上に存在します。デバイスを移行しても、一緒には移動しません。**

つまり、**クラウドに保存されていません**。だから次のことが起こります。

- **Web やモバイルの Artifacts ビューには表示されない**（公式明記）
- **PCを買い替えたら引き継がれない**
- 別の端末からは**そもそも存在しない**

「iPhone の一覧に出てこない」のは**不具合ではなく設計どおり**です。

### 作成・閲覧はデスクトップアプリ専用

- **Claude Desktop（macOS / Windows / Linux beta）でのみ**作成・閲覧可能
- 作り方は2通り: **Cowork タスク内で Claude に直接依頼**する、または **Artifacts サイドバーから「New artifact」→「Create Cowork artifact」**を選ぶ
- **有料プラン（Pro / Max / Team / Enterprise）が必要**で、最新版の Claude Desktop が前提

> **なぜ「iPhone だと公開できる方になる」のか**: ライブアーティファクトはデスクトップアプリ専用なので、**iPhone から作れるのは必然的に①チャット側**になります。「iPhone だから」ではなく「**どの画面で作ったか**」で種類が決まる、というのが正確な理解です。

### データ更新 — 本来は「自動」

ここが重要な訂正ポイントです。**ライブアーティファクトは、本来は自動で最新データを取得します。**

- **開くと、接続済みアプリから最新データを取得**する
- 内蔵キャッシュにより**すばやく表示**し、**バックグラウンドで再クエリ**する
- **ヘッダーの更新ボタン**で強制的に新しいデータを取得できる

「ライブ」という名前は伊達ではなく、**仕組みとしては自動更新型**です。

### ⚠️ それでも「更新されない」ことがある — 2つの原因

仕組みが自動更新型でも、実際には更新されないケースがあります。**原因は主に2つ**です。

**原因A: 中身がコネクタを呼ばない「静的HTML」になっている**

Claude が生成した HTML が、**コネクタを呼び出す作りではなく、取得済みデータをHTMLに直接埋め込んだ静的なページ**である場合、当然ながら開き直しても内容は変わりません。「ライブアーティファクトとして作られた」ことと、「中身がライブにデータを取りに行く作りになっている」ことは**別問題**です。

作成を依頼するときに、**「開いたときにコネクタから最新データを取得する形にして」と明示**するのが確実です。

**原因B: リモートセッションから作成した**

**リモートセッションから作成したアーティファクトは、コネクタ権限が付与されない状態で始まります**。この場合、そもそもコネクタを呼べないため、静的なページになります。

### コネクタの扱い — セキュリティ上の注意

公式が明記している重要な挙動です。

> **ライブアーティファクトは、確認なしにあなたのコネクタを使用します。** 作成・更新時に承認されたコネクタのみにアクセスしますが、**セッションモードが通常なら承認を要求する場合であっても、アーティファクトはコネクタ使用前に許可を求めません**。

つまり、**開いた瞬間に、承認済みコネクタへ自動的にアクセスしにいきます**。社内データに接続したダッシュボードを作る場合は、この挙動を前提に扱う必要があります。

### 共有・公開はプラン依存（Pro / Max は不可）

| プラン | ライブアーティファクトの共有・公開 |
|:---|:---|
| **Pro / Max** | **共有も公開も不可** |
| **Team / Enterprise** | **組織内で共有可能**（リンクは **Claude Desktop でのみ動作**） |

**Pro / Max で「京都旅行プランのような公開リンクが出せない」のは、これが理由**です。①のチャットアーティファクトなら Free でも公開できるため、同じ「アーティファクト」でも真逆の扱いになります。

### 共有時は「閲覧者の権限」で動く

Team / Enterprise で共有した場合の挙動も独特です。

> **共有されたアーティファクトは、あなたのアクセス権ではなく閲覧者のアクセス権を使います。** 誰かがあなたのアーティファクトを開くと、**その人のコネクタとデータソースに接続**します。閲覧者が元のデータソースへのアクセス権を持たない場合、**その部分はあなたのデータではなくエラーを表示**します。

「自分の画面では見えているのに、共有相手には一部がエラーになる」のは**仕様どおり**です。共有前提で作るなら、**各セクションに「どのコネクタが必要か」を示すフォールバック文言を入れておく**と、受け取った側が対処しやすくなります。

## 4. ③ Claude Code のアーティファクト

Claude Code のセッション成果を、claude.ai 上のライブなWebページとして発行する機能です。

### 特徴

- URL は **`claude.ai/code/artifact/<id>`**
- 一覧は**専用ギャラリー `claude.ai/code/artifacts`** に集約される（**チャットのサイドバーには出ない**）
- 発行できるのは **Claude Code CLI（v2.1.183以降）** または **Claude デスクトップアプリ（v1.13576.0以降）**。**モバイルアプリからは発行不可**
- **Anthropic API 経由のセッションのみ**対応（Bedrock / Vertex / Microsoft Foundry では利用不可）
- セッションが進むと**同じURLのまま更新**される（republish）

### 共有

| プラン | 共有範囲 |
|:---|:---|
| Pro / Max | **公開リンクのみ**（リンクを知っていれば誰でも閲覧可・サインイン不要） |
| Team / Enterprise | 組織内の特定メンバー／組織全員への限定共有。管理者が許可すれば公開リンクも可。**編集者（editor）**の指定も可能 |

### コネクタ連携もある（v2.1.209以降）

Claude Code のアーティファクトも、**閲覧時に MCP コネクタを呼んでライブデータを表示**できます。この場合も**閲覧者自身のコネクタ経由**で呼ばれ、**初回は閲覧者に許可を求めます**（ここが Cowork ライブアーティファクトと異なる点です）。なお、**コネクタを呼ぶアーティファクトは公開リンクで共有できません**。

> Claude Code のアーティファクトについては、更新されない場合の切り分け手順を別記事で詳しく扱っています → [Claude Code の Artifact が更新されない](/mdTechKnowledge/blog/claude-code-artifact-update-issues/)

## 5. 見分け方 — いま自分はどれを使っているか

迷ったら、次の順で判定できます。

```
Q1. どこで作った？
 ├─ Claude Code の CLI / デスクトップのコーディングセッション
 │    → ③ Claude Code のアーティファクト
 │      （URL に /code/artifact/ が入る。一覧は claude.ai/code/artifacts）
 │
 ├─ Claude Desktop の Cowork タスク
 │    → ② ライブアーティファクト
 │      （ローカル保存。Web/モバイルには出ない。ヘッダーに更新ボタン）
 │
 └─ claude.ai の通常の会話（Web / デスクトップ / モバイル）
      → ① チャットのアーティファクト
        （サイドバーの Artifacts。Publish で公開リンク）
```

**もっと簡単な判定方法**もあります。

- **スマホの Claude アプリで見えるか** → 見えるなら**①**、見えないなら②か③
- **`claude.ai/code/artifacts` を開いて載っているか** → 載っているなら**③**
- **デスクトップアプリにしかなく、ヘッダーに更新ボタンがあるか** → **②**

## 6. よくある誤解と、正しい理解

実際に混乱しやすいポイントを、誤解と訂正の形で整理します。

| よくある誤解 | 正しい理解 |
|:---|:---|
| 「アーティファクトは1種類で、画面が違うだけ」 | **3種類の別機能**。保存場所（クラウド / ローカル）から違う |
| 「PCで作ったのにスマホに出ないのは不具合」 | **②はローカル保存・デスクトップ専用**なので**仕様どおり**。③も専用ギャラリー側にある |
| 「ライブアーティファクトは自動更新しない」 | **仕組みとしては自動更新する**（開くと最新取得＋手動更新ボタンあり）。更新されないのは**中身が静的HTML**か**リモートセッション由来でコネクタ権限がない**ため |
| 「どのアーティファクトも公開リンクを出せる」 | **②は Pro / Max では共有も公開も不可**。①は Free でも公開可能という**真逆の扱い** |
| 「iPhone だと公開できるものになる」 | 正確には「**どの画面で作ったか**」で決まる。iPhone からは②を作れないので、結果的に①（公開できる方）になる |
| 「公開を解除して、直してまた公開すればいい」 | **公開解除は一方通行**。同じアーティファクトは**二度と公開できず**、永続ストレージのデータも削除される |
| 「共有すれば相手にも同じものが見える」 | **②は閲覧者の権限で動く**。相手がデータソースにアクセスできない部分は**エラー表示**になる |

## 7. 実務上の使い分け

| やりたいこと | 使うべきもの |
|:---|:---|
| 誰にでも見せられる公開ページを作りたい | **① チャットのアーティファクト**（Free でも公開可） |
| スマホからも見返したい | **①**（②③はモバイルの一覧に出ない） |
| 社内データを常に最新の状態で見るダッシュボード | **② ライブアーティファクト**（ただし Pro / Max では共有不可なので個人利用に限る） |
| チームで共有するライブダッシュボード | **②＋Team / Enterprise プラン**（閲覧者権限で動く点に注意） |
| コーディングセッションの成果をレビュー用に共有 | **③ Claude Code のアーティファクト** |
| リンクを長期間安定させたい | **①または③**。ただし**公開解除は避ける**。安定性が最重要なら自前ホスティングも検討 |

## まとめ

- Claude の「アーティファクト」は**同名の別機能が3種類**。**保存場所・一覧・共有可否・更新の仕組みがすべて違う**ため、1つだと思って扱うと症状の原因を読み違える。
- **② Cowork のライブアーティファクトだけが「あなたのコンピュータ上に存在する」**。端末をまたげず、Web / モバイルの一覧にも出ないのは**仕様**。
- **「ライブ＝自動更新」は正しい**。ただし**中身がコネクタを呼ばない静的HTMLなら更新されない**し、**リモートセッション由来だとコネクタ権限がない状態で始まる**。作成時に「開いたときにコネクタから取得する形で」と明示するのが確実。
- **公開解除は一方通行**で、永続ストレージのデータも消える。**「止めて直して再公開」はできない**——ここだけは全種類共通で、事前に知らないと取り返しがつかない。
