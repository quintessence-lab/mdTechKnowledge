> ## 要点
>
> - **Projects は「増え続ける関連タスクを1つの会話に投げ込む」ための仕組み**です。Claude がコーディネーターとして作業ごとに**スレッド**を起こし、各スレッドは通常**クラウドセッション**として並列に動きます。自分でセッションを振り分けたり、同じ前提を毎回書き直したりする手間をなくすのが狙いです（公式の説明）。
> - **パブリックベータ**で、対象は **Pro / Max / Ultra**。**Team・Enterprise は未提供**です。段階展開で、まずクラウドセッションの利用歴があり、claude.ai チャット／Cowork に既存のプロジェクトがないアカウントから始まりました。サイドバーまたは **More** に **Projects** がなければ未到達で、ウェイトリストがあります。
> - **使える場所は claude.ai/code・デスクトップアプリの Code タブ・モバイルアプリ（iOS/Android）**。ターミナルの CLI、VS Code、JetBrains、Amazon Bedrock・Google Cloud の Agent Platform・Microsoft Foundry 経由では使えません。
> - **別料金はなく、通常のプラン上限を消費します**（単一セッションより速く減る。公式は Pro では特に注意と明記）。**新規スレッドは全プロジェクト合計で1日500件**が強制上限です。
> - **制限**: プロジェクトは**1ユーザー専有**（共有不可・組織管理機能なし）、スレッドの移動・コピー不可、クラウドのサンドボックス再開に失敗すると**未コミットの変更が失われうる**ため、長いタスクはこまめに commit/push させます。
>
> ※本稿は 2026年10月31日時点の公式ドキュメント（[Let Claude coordinate ongoing work with Projects](https://code.claude.com/docs/en/claude-projects)）に基づきます。ベータのため仕様は変わりえます。

## 1. Projects とは何か

公式は Projects を「**関連する作業の流れを Claude に調整させる、1つの継続した会話**」と説明しています。やってほしいことを会話に伝えると、Claude が作業ごとにスレッドを起こします。

- **プロジェクトの会話**: Claude がコーディネーターとして動く、長く続く1本のセッション。受け取った内容をスレッドにするか決め、起こしたスレッドを追跡します。見えるのはスレッドが報告してきた内容で、各ステップの細部までは見ません。
- **スレッド**: 実際に作業するワーカー。それぞれ**独立したセッションで独自のコンテキストウィンドウ**を持ち、1つの作業をして会話に報告します。クラウドのスレッドは**独自のブランチ**で作業し、必要に応じてプルリクエスト（PR）を開きます。
- **Overview ペイン**: スレッドを状態別に一覧し、どれが自分を待っているかを示す画面。

プロジェクトがない場合、複数セッションを回すには「各セッションに何をさせるか決める」「毎回同じ背景を書く」「どれが終わったか・返事待ちかを見に行く」を自分でやる必要があります。プロジェクトでは次のように変わります。

| やりたいこと | プロジェクトでの扱い |
|---|---|
| 作業を1か所に送る | バグ報告、スタックトレース、タスク一覧を会話に貼る。Claude が作業ごとにスレッドを起こすか、その領域を担当中のスレッドへ渡す。簡単な質問はその場で答える |
| 文脈を一度だけ設定する | 新しいスレッドはすべてプロジェクト指示から始まる。ターゲットブランチのような規則を一度書けば全スレッドに届く |
| 離席して終わった作業を見る | 1時間後や翌朝に Overview で、終わったスレッド・レビュー待ちの PR・返事待ちのスレッドを確認 |

## 2. 提供状況と使える場所

| 項目 | 内容（公式ドキュメント） |
|---|---|
| ステータス | パブリックベータ、段階展開 |
| 対象プラン | Pro / Max / Ultra（Team・Enterprise は未提供） |
| 展開の順序 | クラウドセッションを使ったことがあり、claude.ai チャット／Cowork に既存プロジェクトがないアカウントから |
| 見つけ方 | claude.ai/code または デスクトップの Code タブで、左サイドバーの **Projects**、なければ **More** の中。ブラウザでは `claude.ai/code/projects/browse` にも直接入れる |
| 未到達の場合 | ウェイトリストに参加。それまでは「Run agents in parallel」（並列エージェントの比較ページ）の選択肢を使う |
| 利用面 | claude.ai/code、デスクトップアプリ、iOS／Android アプリ |
| 使えない面 | ターミナル CLI、VS Code 拡張、JetBrains プラグイン、Amazon Bedrock、Google Cloud の Agent Platform、Microsoft Foundry |

なお、claude.ai チャット／Cowork の**従来の「Projects」**（会話と参照ファイルをまとめる機能。スレッドもコーディネーターもない）は別物で、新しい体験が届くまで今までどおり動きます。「New project」の代わりに **Get started** と表示される場合は、既存の claude.ai プロジェクトを先にアップグレードかアーカイブするよう案内されます。

## 3. どんな仕事に向くか

公式が挙げる向いている仕事は、「**1セッションより長く続く目標があり、タスクが生まれ続ける**」ものです。

- **1つの目標を多数のリポジトリに**: 「全サービスを新しい lint 設定に揃える」。リポジトリごとにスレッドを起こし、それぞれ PR を作り、Overview でレビュー待ちを確認。
- **育て続ける領域**: 1つのサービスのバグ、スタックトレース、レビュー依頼を、届くたびに会話へ貼る。1回の修正のあとで「覚えておいて」と言った落とし穴は、次回以降プロジェクトメモリから効く。
- **1セッションに収まらない構築・移行**: 「`docs/spec.md` の内容を作る」「非推奨 ORM から移行する」。作業が部分ごとのスレッドに分かれ、早い段階で覚えさせた判断は後続のクラウドスレッドに届く。
- **コードではない仕事**: 契約書のフォルダやサポートチケットのエクスポートに繰り返し質問する（例:「チケットから多い連携ミスを10個挙げて」）。リポジトリの代わりに文書をアップロードし、各スレッドの成果物は **Library** タブにファイルとして届く。

まとめて指示を投げ、「確認せずに開始して」と伝えて離席する使い方もできます。戻ったら **Waiting on you** で自分を待つスレッドを探します。作業の一部を定期実行にしたいときは、Claude に頼んで**クラウドのスケジュールタスク**（Routines）にできます。

## 4. 構成: 会話・スレッド・Overview

### 4-1. すべてのクラウドスレッドが最初に持つもの

- プロジェクトの**リポジトリとファイル**、**プロジェクト指示とメモリ**
- 各リポジトリの **`CLAUDE.md`**（ただしリポジトリの skills、`.claude/settings.json`、`.mcp.json` は読まない）
- claude.ai アカウントの**コネクタ**
- ネットワーク・環境変数・シークレット・導入ツールを定める**クラウド環境**

自分の PC の Claude Code 設定はクラウドスレッドには引き継がれません。

### 4-2. Overview の状態グループ

| グループ | 内容 |
|---|---|
| Ready for review | PR が開いてレビュー待ち |
| Waiting on you | 返答・承認が必要、または失敗したスレッド |
| Working | 実行中 |
| Landing | PR が承認済み、またはマージ待ち |
| Idle | 終わって、何も待っていない |
| Resolved | 完了とされたもの（自分がメニューで、Claude が最後の手順の後で、または**1週間動きがなければ自動**）。同じメニューから再開できる |

Overview の他のタブは **Library**（追加したファイルとスレッドの成果物）、**Pull requests**（スレッドが開いた PR）、**Scheduled tasks**（このプロジェクトから作ったスケジュールタスク）です。デスクトップアプリでは、Claude の投稿・スレッドのエラー・入力待ちでデスクトップ通知が出ます（ブラウザでは Overview ボタンのドットで確認）。

### 4-3. スレッドの PR の扱い

コードを変更するクラウドスレッドは、特に指示がなければ次のように動きます。

- **ブランチ**: リポジトリのデフォルトブランチから新しいブランチを切る
- **PR**: 頼まれたとき、またはバグ修正など具体的な変更では自分から開く
- **開いたあと**: **auto-fix を有効にして PR を監視**する（他のクラウドセッションで auto-fix がオフでも）。CI が失敗すれば修正を push、レビューコメントに対応し、チェックが通れば返信する

スレッドのカードには **Resolve conflicts／Fix CI／Address comments／Merge it**（自分からスレッドへの指示として送られる）、**Review PR**（GitHub で開く）、**Create PR**（ブランチを push 済みで PR 未作成のとき、直接 PR を作る）のボタンが出ることがあります。

## 5. 作り方

### 5-1. 事前確認

- **プラン**: Pro/Max/Ultra で、サイドバー（または More）に **Projects** があり、**New project** または **Get started** が出る
- **GitHub（コードを扱う場合）**: github.com 上のコードであること（GitHub Enterprise Server・GitLab・Bitbucket は対象外）、連携した GitHub アカウントに push 権限があること、**Claude GitHub App** がそのリポジトリに入っていること。`/web-setup` で渡したトークンは他のクラウドセッションには使えても、プロジェクトのクラウドスレッドには足りず、Claude GitHub App が必要
- **ネットワーク・シークレット・ツール**: プロジェクトの**クラウド環境**で決まる。既定環境は一般的なパッケージレジストリには届く。MCP サーバーが必要なら claude.ai のコネクタで接続済みか確認

組織所有のリポジトリでは、GitHub App のインストールを完了できるのは**組織のオーナー**だけです。SAML SSO を強制する組織は、Claude アプリの認可が済むまで、そのプライベートリポジトリが New project のダイアログに出てきません。

### 5-2. ゼロから作る

1. 左サイドバーの **Projects** → **New project**（**Get started** と出たら既存プロジェクトの整理が先）
2. ダイアログで入力: **Name**（必須）、**Goal**（任意。例:「API の p95 レイテンシを200 ms 未満に保つ」）、**Context**（任意。GitHub リポジトリ、ファイル、フォルダ、Google Drive フォルダ）
3. **Create project** を押す

公式は、**1つの流れの仕事に絞る**こと、リポジトリは「ほとんどのタスクが必要とするもの」だけを足し、全部は入れないことを勧めています。最初のプロジェクトでは、作成直後に Claude が自分で1ターン動くことがあり（プランを消費）、リポジトリを読み取り専用で調べるスレッドを1つ起こしたり、直近のクラウドセッションから **Setup recommendations**（追加すべきリポジトリ、作るべきスケジュールタスク、起こせるスレッド）を提案したりします。

### 5-3. 既存のクラウドセッションから作る

作業中のクラウドセッションのサイドバーメニューで **Continue in project** → **Continue as new project**（または既存プロジェクトを選択）。Claude がセッションを読んで Setup recommendations を出します。元のセッションは残り、ターンの途中なら動き続けるので、二重に動かしたくなければ自分で止めます。

自分の PC のセッションは、Remote Control で接続すれば同じメニューが使えます。ただし**アカウントで Require trusted devices が有効だと、プロジェクトからそのセッションの記録を読めません**。

### 5-4. 最初のバッチの前にやること

公式が勧める順序です。

1. **プロジェクト指示を書く**（ターゲットブランチ、完了前の自己確認、足りないものがあったときの動き、事前承認が要る操作）
2. 実作業を**小さく1つ**送り、スレッドの報告の仕方とブランチの中身を確認する
3. **Project settings > General** の **Thread model／Thread effort** を確認する。**新規プロジェクトは全スレッドが Opus・high effort**（会話側は low effort）で動き、プランを最も速く消費する設定
4. 「スレッドは提案してから起動」「同時に数本まで」と頼み、思い通りに動くのを確認してから制限を外す

## 6. 共有コンテキスト: 指示・メモリ・リポジトリ・ファイル

| コンテキスト | 内容 | 設定方法 |
|---|---|---|
| プロジェクトメモリ | 要件・判断・落とし穴などのメモをファイルとして保存。クラウドスレッドは開始時に索引 `MEMORY.md` を読み、他のファイルは必要時に開く | 会話やクラウドスレッドで「覚えて／忘れて」と頼む。**Project settings > Memory** で閲覧・編集・削除 |
| プロジェクト指示 | 新しいスレッドとプロジェクトの会話に送られるテキスト。**最大16,000文字** | **Project settings > Memory > Project instructions**、または Claude に変更を頼む |
| リポジトリ・ファイル・環境 | 全クラウドスレッドが clone するリポジトリ、`/mnt/project-files` 配下で読めるファイル、実行するクラウド環境 | **Project settings > Environment**、または Library の **Add** |

注意点:

- プロジェクトメモリは `MEMORY.md` 索引を使う点でローカルの auto memory と似ていますが、**別物**です。**Auto memory** の見出しで一覧されるのは、Claude が作業中に自分で書くためです。
- プロジェクトメモリは、各リポジトリの `CLAUDE.md` とも別です。**リポジトリに関する指示は `CLAUDE.md`、プロジェクト全体のメモはプロジェクトメモリ**に置き分けます。
- 「スレッド数は2つまで」のような指示を会話で伝えると、Claude が自分でプロジェクトメモリに保存して以降のスレッドで守りますが、**強制される設定ではなく「Claude が守る指示」**です。厳密に効かせたいなら、プロジェクト指示に書きます。

### 6-1. 指示に書くとよいこと（公式の例から）

プロジェクトの目的、作業場所（リポジトリ・起点ブランチ・PR の命名）、完了前の自己確認（例: `make test` と `make lint`）、必要なものが足りないときの動き（「不足を最初のメッセージで明示して止まる。代用・モック・推測はしない」）、事前承認が要る操作（マージ、force-push、CI 設定の変更）。

### 6-2. リポジトリから拾われるもの・拾われないもの

クラウドスレッドは、プロジェクトに追加した各リポジトリから **`CLAUDE.md` のみ**を読みます。

| リポジトリ側 | クラウドスレッドでの扱い |
|---|---|
| ルートの `CLAUDE.md`、`.claude/CLAUDE.md`、`.claude/rules/` | 開始時に全リポジトリ分を読み込む。**サブディレクトリの `CLAUDE.md` とパス指定ルールは読まない** |
| `.claude/skills/` の skills | 読まない。claude.ai アカウントで有効化した skills を使う |
| `.claude/` の agents・commands | 読まない。使うなら自分の PC でスレッドを動かす |
| `.mcp.json` の MCP サーバー | 読まない。claude.ai のコネクタを使う |
| `.claude/settings.json` の plugins | 読まない。**Project settings > Plugins** で追加 |
| `.claude/settings.json` の permission rules | 適用されない。スレッド内で承認するか、自分の PC で動かす |
| `.claude/settings.json` の hooks | 動かない。使うなら自分の PC で動かす |
| `.claude/settings.json` の `env` | 適用されない。クラウド環境側で設定 |

プロジェクトの会話自体にコネクタはないため、コネクタが要る作業は**クラウドスレッドへのタスクとして**送ります。

### 6-3. リポジトリを追加するか、都度追加させるか

プロジェクトに入れると全クラウドスレッドが clone し、`CLAUDE.md` も最初から読みます。入れずにおくと、タスクが必要としたクラウドスレッドが**そのスレッドだけに**自分で追加できます（スレッドにその旨のメモが出る）。この場合は clone が作業の途中なので、**そのリポジトリの `CLAUDE.md` はスレッド開始時にはなく**、次のスレッドも読み込まずに始まります。複数リポジトリにまたがる場合は、ほぼ全タスクが触る1〜2個を入れ、残りはプロジェクト指示で場所を教えます。また**プロジェクトにリポジトリが1つ以上あると、Claude が追加できるのは、そのプロジェクトが既に使っている GitHub オーナーのリポジトリのみ**です。別のオーナーのものは自分で Project settings から足します。

リポジトリなしのプロジェクトも作れます。クラウドスレッドは自分のサンドボックスで調査・文書作成・コードの実行ができ、成果物は **Library** タブに届きます。

### 6-4. ファイルとフォルダの上限

| 対象 | 上限 |
|---|---|
| Library タブで追加 | 1回に最大100ファイル・2 GB、単一ファイルは最大480 MB |
| New project ダイアログ | 30 MB を超えるファイルはスキップ（大きいものは作成後に Library から） |
| フォルダ追加 | 先頭100ファイル・最大200 MB。30 MB 超のファイル、隠しファイル、`node_modules` は除外 |
| フォルダ数 | フォルダと Google Drive フォルダの**合計で10個まで**（単一ファイルは数えない） |

アップロードは**コピー**なので、PC 側の変更は反映されません。再アップロードして **Replace** を選びます。

## 7. 自分の PC でスレッドを動かす（Remote Control）

ローカルのデータベース、デバイスエミュレータ、VPN の内側の API など、**自分の PC にしかないもの**が必要な作業は、Claude に頼んで**そのタスクのスレッドだけを自分の PC で**動かせます。プロジェクトの他のスレッドはクラウドのままです。

PC 側のスレッドは、クラウドスレッドと次の点で異なります。

- その PC のファイル、ツール、MCP サーバー、Claude Code 設定（**フックと権限ルールを含む**）で動く（クラウド環境ではない）
- **プロジェクト指示は受け取るが、メモリファイルは読み込まれない**
- **その PC が起きていて Remote Control が有効な間だけ**動く

手順（公式）:

1. **フォルダを接続**（どちらも Claude Code **v2.1.280 以降**が必要）— デスクトップアプリの **Settings > Code**（または Claude Code）で **Use this computer from your phone and claude.ai** をオンにしてフォルダを追加、またはターミナルでそのフォルダで `claude remote-control` を実行して起動したままにする（git リポジトリでは `--spawn worktree` で各スレッドに専用の worktree を割り当て可）
2. **Work locally** で依頼 — プロジェクトの会話の **+** メニューから **Work locally** を選ぶ（メッセージに「自分の PC で」と書いてもよい）
3. **カードで許可** — **Allow Claude to work in a folder on your device** のカードでフォルダを選び（複数接続時）、**Allow once** を押す。同じフォルダで2つのスレッドが同時に動くと変更を上書きし合うため、git リポジトリなら **Worktree** をオンにして専用 worktree を与えられる

このスレッドも、利用可能なら auto mode で動き、フォルダ内のコマンド実行・ファイル編集を毎回の確認なしに行います。auto mode が使えない場合は、権限プロンプトがスレッド内で返答待ちになります。PC がスリープするとスレッドは**一時停止**し、デスクトップアプリや `claude remote-control` が終了すると停止します。スリープ防止はデスクトップの **Keep this computer awake for Remote Control** で設定できます。**Require trusted devices がオンのアカウントでは、PC でスレッドを動かせません。**

## 8. 使用量と費用

- **別料金はありません**。プロジェクトの使用量は、他の Claude Code セッションと**同じプラン上限**に加算され、プロジェクトが単独で上限を超えて使うことはできません。
- 公式は「**単一セッションより速く上限に近づく**。特に Pro プランは、プロジェクトを回した日に上限へ早く達すると想定してほしい」と明記しています。
- 上限に達したスレッドは**待機し、リセット後に自動で再開**します（**スケジュールタスクが起こしたスレッドは待たずに**上限エラーで止まるため、リセット後にメッセージを送る）。待機が不要なら、スレッドで **Stop**、またはプロジェクトを **Pause** します。
- プランの上限を超えて使えるのは、アカウントで **usage credits** を有効にしている場合のみ。スレッドが勝手に有効にすることはできません。

### 8-1. 使用量を食う要素

| 要素 | 内容 |
|---|---|
| 実行中のスレッド | それぞれが完全なセッション。**同時実行数に固定の上限はなく**、Claude が必要なだけ起こす。「同時に2本まで」は希望であって上限ではない。**強制される上限は、全プロジェクト合計で1日500スレッド** |
| 会話 | スレッドの報告を読み、次を決めるために Claude 自身もトークンを使う |
| PR を監視しているスレッド | アイドル中でも、CI の失敗やレビューコメントで**起き上がってプランを消費**する。止めたければスレッド内で PR 監視をやめるよう頼む |

実行中のスレッド・監視中の PR・新しいメッセージがなければ、**待機中のプロジェクトは消費しません**（アーカイブ済みも同様）。

### 8-2. 抑える方法

**Project settings > Usage** で、スレッド別・モデル別・会話ぶんのトークン使用量を確認できます。公式の抑え方は次のとおりです。

- Pro/Max/Ultra のプラン内では**キャッシュ寿命は1時間**。それより長く放置したスレッドに追い指示を送ると、**会話全体を読み直して**から動く。新しい仕事は、古い大きなスレッドを起こすより**新しいスレッド**のほうが安く済むことがある
- 重くない作業は、スレッド・会話それぞれで**小さいモデルや低い effort** に変える（**Thread model／Thread effort／Coordinator model／Coordinator effort**）
- 会話に「同時に動かすスレッドを減らして」「小さな質問は自分で答えて」と頼む

## 9. 運用: 承認・調整・停止

- **承認待ち**: スレッドは、モデルが対応していれば **auto mode** で動くため、大半のツール呼び出しは確認なしに進みます。承認が要るときのプロンプトは**そのスレッドの中**に出て、そこで答えるまで待ちます。**会話で「進めて」と言ってもスレッドには届きません**。クラウドスレッドは**リポジトリの `.claude/settings.json` の権限ルールを読まない**ので、頼れるのは auto mode とスレッド内の承認です。
- **調整の言い方**（公式の例）: 「スレッドは提案してから起動して」「確認なしで今すぐ開始して」「同時に最大2スレッド」「同じ領域の追い指示は既存スレッドを再利用して」「更新は短く／終わったときと詰まったときだけ」「全スレッドの状況を報告して」「このタスクは小さいモデルで」「計画を見るまで PR を開かないで」「何が問題か教えて、まだ直さないで」「それはここで答えて（スレッドは起こさないで）」。
- **スレッドを直接操作**: カードや Overview の行をクリックしてスレッドの記録を開き、手順の確認、そのスレッド自身の入力欄での指示、権限プロンプトへの回答、**Stop**（または Esc）による中断ができます。プロジェクトの会話での追い指示は、Claude がそのスレッドに紐づけた場合にだけ届きます。
- **Pause／Archive／Delete**（Project settings > General の下部）:
  - **Pause**: 実行中のスレッドと会話を中断し、新規スレッドの起動とスケジュールタスクを止める。**Resume** で再開
  - **Archive**: サイドバーから隠し、スレッドをアーカイブして監視中のものも止める。スケジュールタスクも動かない。**Unarchive** で戻すが、スレッドは個別に戻す必要がある
  - **Delete**: プロジェクト、スレッド、メモリ、ファイルを**完全に削除**し、スケジュールタスクも止める。元に戻せない。スレッドが GitHub に push したブランチと PR は影響を受けない
- **コンテキスト管理は不要**: スレッドは自動で compact され、会話は直近のメッセージ・直近のスレッド・プロジェクトメモリから動くため、プロジェクトが続く限り続きます。**絶対に落としたくない内容はプロジェクトメモリに置きます。**

## 10. 制限事項

| 制限 | 内容 |
|---|---|
| 利用面 | CLI／VS Code／JetBrains、Bedrock・Google Cloud の Agent Platform・Foundry では不可 |
| モデル提供元 | クラウドスレッド・PC のスレッドとも Anthropic がモデル提供元 |
| 自分の PC のセッション | 自分で始めた PC のセッションをプロジェクトに**追加することはできない**（作業内容を取り込むことはできる）。PC に届くのは Remote Control 経由のスレッドとして |
| サンドボックスの再開 | クラウドスレッドのサンドボックスはターン間で一時停止し、続行時に再開する。**再開に失敗すると新しい clone から続ける**ため、**未コミットの変更が失われうる**。長いタスクでは、作業中の変更を commit/push するよう頼む |
| 共有・組織管理 | プロジェクトは**1ユーザー専有**。プロジェクトやスレッドを他のユーザーと共有できず、スレッドの記録には他のクラウドセッションにある共有オプションもない。**ベータ中は組織レベルの管理機能もない** |
| スレッドの移動 | スレッドは起こしたプロジェクトに属し、他のプロジェクトへの移動・コピーも、独立への切り出しもできない。**Continue in project** は逆方向（セッション→プロジェクト）のみ。2つのプロジェクトの統合もできない |

トラブルシューティングで公式が挙げる主なものは、スレッドが止まって見える（Claude は各ステップを投稿しないため、動いていることが多い。記録を開いて確認）、スレッドが推測で進めた・止まった（共通の原因はプロジェクト設定の不足が多い。会話に「全スレッドについて、頼んだこと・仮定したこと・届かなかったもの・待っているものを列挙して」と頼む）、「Claude hasn't responded」（**Restart Claude**）、リポジトリへのアクセスエラー（Claude GitHub App の導入・連携の不備）、使用量上限、`Claude is out of date on your device`（PC 側の Claude Code が v2.1.280 より古い）などです。

## 11. 他の機能との使い分け

公式ドキュメントの「Projects が向かないケース」と「関連機能との関係」を、並べて整理します。

| やりたいこと | 向く手段 | 理由（公式の整理） |
|---|---|---|
| 1つのセッションに収まる単発の作業（例:「不安定なログインテストを直す」） | **クラウドセッション**を自分で起動 | プロジェクトにする必要がない |
| すべてのタスクが自分の PC を必要とする作業（ローカル DB、エミュレータ、VPN 内の API） | **ローカルセッション**、または複数同時なら **Agent View** | ローカルのファイルだけで足りるなら、プロジェクトにアップロードする手もある |
| 会話を伴わず、同じ作業を定期的に繰り返すだけ（例:「毎週月曜に依存関係レポートを投稿」） | **クラウドのスケジュールタスク（Routines）** を単独で作る | プロジェクトは不要 |
| Slack のチャンネルで複数人が Claude に仕事を渡して一緒に調整する | **Claude Tag** | プロジェクトは自分専用。Claude Tag は Team／Enterprise プランの Slack 向けで、チャンネルの全員が見て調整でき、管理者が設定した接続を使う |
| 1つのタスクのために複数のエージェントを走らせる | **Agent teams／サブエージェント** | 下記 |

**関連機能との関係（公式）**:

- **クラウドセッション**: すべてのスレッドは、PC で動かすよう頼まない限りクラウドセッション。違いは、**起動と追跡を Claude が行う**こと。
- **スケジュールタスク（Routines）**: プロジェクト内で定期実行を頼むと、クラウドのスケジュールタスクが作られ、**プロジェクトのスレッドとして走り**、Scheduled tasks タブに出ます。プロジェクト外で作ったスケジュールタスクは独立して動き続けます。
- **Remote Control**: PC でスレッドを動かすとき、プロジェクトはこれを使います。
- **ローカルセッションと Agent View**: 自分で起動したセッションはプロジェクトの外。Agent View は複数のローカルセッションを並べて追跡する画面で、**各セッションの起動とタスクの付与は自分で行う**。
- **Worktree**: ローカルセッションに専用の作業コピーを与える仕組み。クラウドスレッドは各自がサンドボックスに clone して自分のブランチで作業するので不要。
- **Agent teams**: 1つのタスクのために teammate セッションを起こす単一セッションで、**そのタスクとともに終わる**。
- **サブエージェント**: 1つのセッション内で、副次タスクを自分のコンテキストで実行して要約を返す。プロジェクトのスレッドは Claude が起こす完全なセッションで、**スレッド自身はサブエージェントを使える**。

### 11-1. サイト内の関連機能との位置づけ（本稿の整理）

以下は、公式ドキュメントが直接比較していない関連機能との関係を、当サイトの既存記事とあわせて整理した**本稿の見立て**です。

| 比較対象 | 本稿の整理 |
|---|---|
| [Dynamic Workflows](/mdTechKnowledge/blog/claude-code-dynamic-workflows-guide/) | 公式の整理では、並列エージェントの機能は**単一セッション内**で完結する（Agent teams・サブエージェント）のに対し、Projects は**複数の独立したクラウドセッションを会話が束ねる**構造。Dynamic Workflows をどう位置づけるかは公式ドキュメントに明示がないため、両者を併用する場合は実機での確認が必要 |

## 12. 導入前チェックリスト

- [ ] プランは Pro/Max/Ultra か。サイドバーまたは More に Projects があるか（なければウェイトリスト）
- [ ] コードは github.com 上か。Claude GitHub App を入れられるか（組織なら**オーナーの承認**、SSO 組織は認可）
- [ ] 作業は「1セッションより長く続き、タスクが増え続ける」ものか（単発・定期のみ・全タスクがローカル必須なら別手段）
- [ ] リポジトリ側の規則は**ルートの `CLAUDE.md`／`.claude/rules/`** にあるか（skills・`.mcp.json`・hooks・権限ルールは読まれない）
- [ ] 必要な skills はアカウントで有効化済みか。必要な MCP はコネクタとして接続済みか
- [ ] **Thread model／effort** を作業に見合った設定にしたか（新規は Opus・high で消費が速い）
- [ ] 最初は**小さな作業1つ**で挙動を確認し、「提案してから起動」「同時数」の希望を伝えたか
- [ ] 長いタスクで**こまめな commit/push** を指示に入れたか（サンドボックス再開失敗に備える）
- [ ] PR を監視中のスレッドが**アイドル中も消費する**ことを理解したか。不要なら PR 監視の停止を頼む
- [ ] 共有や組織管理が必要でないか（**1ユーザー専有**・管理機能なし）
- [ ] 1日500スレッドの上限と、プランの5時間／週間の上限に当たったときの待機動作を理解したか

## 13. まとめ

Claude Code Projects は、**「増え続ける関連タスクの振り分け・前提の共有・進捗確認」を Claude に任せ、各作業を独立したクラウドスレッドで並列に進める**ための、Pro/Max/Ultra 向けのパブリックベータ機能です。強みは、**一度書いた指示とメモリが全スレッドに届く**こと、**ラップトップを閉じても続く**こと、Overview で**自分を待つスレッドだけを見に行ける**ことです。一方で、**1ユーザー専有**、**CLI や IDE からは使えない**、**リポジトリ側の skills・hooks・権限ルールが読まれない**、**プラン上限を速く消費する**といった制約があるため、単発作業・定期実行のみ・全タスクがローカル必須の仕事には他の手段のほうが合います。
